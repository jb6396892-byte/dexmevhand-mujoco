# 两段视频到桌面视觉抓取：答辩材料

本轮目标是准备可训练、物理可执行的两类示范，**不启动训练，不做独立留出测试**。
最终数值以 `evidence/summary.json` 和 `development-matrix.json` 为准。

## 建议讲述顺序

1. **问题定位**：第二视频冻结参考中的杯轴朝下。直接刚体映射到直立杯，会把抓握时手掌映射到桌面以下约 1–3 cm。仅凭这个仿真参考不能断言原始真实视频中的杯子也是倒置的。
2. **功能重定向**：保留杯柄轴，将参考杯的朝上方向规范化，保留原接近、闭合动作；接近时增加 25 mm 手部净空，350–500 参考步平滑退出。改变的是参考对应关系和手部目标，不是在线写杯子位姿。
3. **物理接触门控**：拇指和至少两个其他手指有承载接触，至少两个法向与拇指相对，连续满足 50 个控制步才允许抬杯。不增加手指闭合力。
4. **稳定抬杯与搬运**：闭合后以本体感知的实际手姿和 RGB-D 杯位姿建立搬运起点，保持闭合姿态，先竖直抬升，再五次平滑插值搬运。第二视频的任务终点在运行前声明为参考终点下方 50 mm，为保持腕姿的直线轨迹留出关节余量；不是执行后移动目标来掩盖误差。
5. **视觉纠偏**：末段每个新视觉帧最多调整手腕平移 3 mm，总预算 50 mm；同一帧不会反复积分。绝对动作、关节、穿透门槛保持不变。
6. **泛化前准备**：两段视频、不同杯子位置/朝向与随参考变换的目标，按完整工况划分训练与开发验证。动作前采集 139 维输入，保留参考时钟和控制时钟；正示范与失败记录分开。

## 关键代码

`src/fromrealhand/tabletop/functional_reference.py` 的 `upright_source_correspondence`：

```python
flip = np.diag([1., -1., -1., 1.])
result = result @ flip
tips = tips @ flip[:3, :3]
```

这是右手系旋转，不是镜像；它保留原世界指尖坐标的表达，但改变杯子的任务对应。第二视频必须标注为**直立杯功能复现**，不能称为原视频姿态的逐帧忠实复现。

`contact_control.py`：参考前馈 + 本体反馈 + 有界视觉位置纠偏，只修改电机动作。`training_inputs.py`：在 `env.step(action)` 前构造输入，成功后才把该样本写入完整正示范。

## 文献与工程边界

- [DexMachina 官方重定向文档](https://mandizhao.github.io/dexmachina-docs/3_retargeting.html)：参考运动学映射和物理执行应分开验证。本轮借鉴流程，不宣称复现其训练算法。
- [FoundationPose 官方示例](https://github.com/NVlabs/FoundationPose/blob/main/run_demo.py)：首次注册后持续跟踪。本轮借鉴流程，没有安装或使用 FoundationPose 网络权重。
- [Open3D 官方 ICP 教程](https://www.open3d.org/docs/release/tutorial/pipelines/icp_registration.html)及[稳健核](https://www.open3d.org/docs/release/tutorial/pipelines/robust_kernels.html)：使用现有配准库；圆柱表面遮挡导致点到面旋转跳变时，重新做点到点配准，仍检查质量和位姿跳变，不直接裁剪旋转结果。

目前的贡献是可审计的工程组合：约束下参考映射、物理阶段门控、闭合后重建搬运起点、视觉纠偏以及动作前训练数据对齐。还没有通过公平对照证明算法创新或优于上述论文。

## 答辩时不能混淆

- 这是**参考动作加反馈的专家控制器**，不是新训练出的自主策略，也不是 MoE 专家模型。
- 开发工况通过不等于泛化成功；种子 101–108 留给冻结后的学习策略，尚未运行。
- 两条真实视频仍然很少，物体尺寸、材质、相机和干扰物布局的覆盖有限。
- 三指对握通过不等于四指视频忠实度通过，也不代表获得了真实接触力标签。
- 没有验证装水、不倾倒、放下杯子或真实机器人部署。
- 新输入 139 维，不能把旧观察维度的 checkpoint 直接载入并称为同一策略。

# F1：整桌场景与物理 XYZ 平台

日期：2026-10-07。范围：**整桌布局、平台运动、到位和制动，不是抓取策略。**

## 查看原生 MuJoCo 窗口

```bash
cd /home/smgbro/mujoconew/GITHUB
bash scripts/177_launch_whole_table_f1.sh
```

默认四件干扰物，平台带着固定姿态的 Adroit 在桌面上方连续移动。改变种子会改变杯子与干扰物位置，不会改变手的初始位置。

```bash
bash scripts/177_launch_whole_table_f1.sh --seed 18 --count 3
bash scripts/177_launch_whole_table_f1.sh --seed 9 --cup-xy 0.35 -0.30
```

杯子坐标单位为米。按 Esc 或关闭窗口退出；`--seconds 10` 用于自动结束的窗口检查。没有 Qt 新模式，也不会执行“闭合手指抓杯”；旧 Qt 仍使用原 v6 入口。

## 具体实现

- 三个平移关节 `gantry_x/y/z`，质量、阻尼、有界伺服执行器和支架/横梁/连接杆碰撞几何。
- XYZ 行程为 X/Y ±0.60 m、Z 0–0.45 m，固定初始状态为 `(0,0,0.30)` m。
- 原始 Adroit 30 个关节和执行器保留，以名称获取索引。平台 qpos 是 0–2，但执行器是 30–32；原手的 qpos 是 3–32、执行器是 0–29。这证明不能按数组前 30 项直接绑定。
- F1 使用相对关节等式约束保持手指和原局部手架的姿态；不是抓取策略，也不是逐帧写手部 qpos。F2 才移除此固定姿态限制、接入局部控制。
- 固定几何标定后，零关节位置的 `S_grasp` 为世界 `(0,0,0.10)` m；平台位移直接叠加，home 时约为 `(0,0,0.40)` m。标定只做一次，不随杯子或种子变化。
- 运动只写平台执行器 ctrl，再 `sim.step()`。重力补偿通过有限力的电机控制输入施加，不对杯子加外力；物体初态仅在初始化设置。
- 使用现有 SciPy `BPoly.from_derivatives` 生成保守静止到静止测试轨迹，不安装新规划库。F1 无障碍寻路；OMPL/Ruckig 的完整避障和时间处理仍属于 F3。
- 刹停保持参考位置、速度、加速度连续，不从存在跟踪滞后的实测位置重新起步。当前验证的是中途受控制动，不是断电急停或硬件安全认证。
- F1 独立配置使用 0.5 ms 物理步长，初始化自由落稳 2 s；不修改旧场景的 2 ms 配置。桌面支撑检查同时记录底部高度和物体速度。

## 整桌物品采样

复用现有 YCB 资产。杯子缩放固定为 0.8、朝向固定；其余 0–4 件物体在全桌采样，允许出现在中央。

从 MuJoCo 编译后的真实网格顶点计算旋转投影包围盒，包含视觉与碰撞网格；按每个物体的尺寸决定允许的中心范围。投影 AABB 是保守占地近似，不是精确二维接触轮廓：会排除一部分包围盒重叠但实体不交的紧密布局，**不会预留机器人行走通道**。

边缘初始余量 5 mm，物体投影盒间距 10 mm。采样时只拒绝几何非法摆放，不做可抓性筛选；没有规划失败后重新抽取布局的逻辑。初始化后让所有桌面物体自由落稳，并用实际姿态和网格重新检查桌面支撑。

注意“全桌”不代表杯子中心可到桌边线：杯体和杯柄必须仍在台面上。实际中心边界由 `mesh-bounds.json` 和旋转后的几何自动决定。

## 验收产物

原始输出放共享盘 `visual_grasp/whole-table-v1/`。`f1-dev-a` 保留首轮到位记录及截图后端失败；`f1-acceptance` 保留刹停不通过的结果；`f1-acceptance-v2` 通过原到位门槛，但尚未检查物体静置速度。`f1-acceptance-v3` 增加低速度检查并补齐平台连接几何。最终归档目录为 `f1-final`。验收包括 20 个随机布局、杯子四个合法极限角点、九宫格连续到位、六个近限位点、七个非法目标拒绝、运动中制动和两张渲染图。

**验收边界：** `passed` 对应任务书 F1 的桌面支撑、穿透不超过 1 mm、平台位置/速度/加速度/限位和制动。新增 `low_velocity` 记录物体瞬时线速度 <10 mm/s、角速度 <0.05 rad/s；它并非原任务书的门槛，不能与几何支撑混为一谈。v3 中仅 11/20 个布局满足这项附加指标；最终报告仍公开该计数，不把没有掉桌表述为完全静止。平台运动阈值从未放宽。

结果归档：[答辩资料](presentation/whole_table/F1_RESULTS.md)。软件测试与复现命令见 [运行日志](run_logs/2026-10-07-whole-table-f1.md)。

## 已修正的问题

1. 网格尺寸目录最初将全部物体放在同一点，触发 MuJoCo 接触缓冲区溢出；尺寸读取场景现将对象分开摆放，仅做 FK，不作为物理验收。
2. 首版竖向连接杆穿过手掌，出现约 30 mm 穿透；将连接杆移到前臂安装端，并把支撑轨道移出手架完整行程，不关闭手掌与环境的碰撞。
3. 默认 EGL 离屏后端初始化失败；截图改用项目已有的 `desktop.rendering.stream_context`，沿用 GLFW/GLX 和 PRIME 环境，不重新安装驱动。
4. 刹停直接以实测 q/v/a 初始化参考，会突然消除约 7 mm 跟踪滞后，形成约 2.07 m/s² 加速度。修正为参考轨迹的 C2 连续交接，未放宽运动阈值。
5. 2 ms 步长下干扰物存在静置抖动；延长等待、关闭 noslip 或降低扭转摩擦的单变量检查均未解决。0.5 ms 步长改善了种子 9，但扩展到全部布局仍未通过所有附加低速度检查；保留原摩擦和 noslip 参数。不是通过锁物体或清零速度“稳定”场景。

已排除的碰撞对仅是理想导轨/安装界面的机构内部接触，关节约束和阻尼承担对应连接。手掌、手指、杆件对桌面物体的碰撞仍存在。

## 参考与下一步

机构按 [MuJoCo 官方运动树与关节建模说明](https://mujoco.readthedocs.io/en/2.1.2/modeling.html#kinematic-tree) 构建；测试轨迹调用 [SciPy 导数边界插值](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.BPoly.from_derivatives.html)。本轮没有下载机器人替代模型。

静置抖动排查参考 [MuJoCo 软约束与滑移说明](https://mujoco.readthedocs.io/en/2.1.2/overview.html#softness-and-slip)：noslip 后处理并非越强越稳定，数值稳定性还受步长影响。本项目用实测对照决定配置，而不是直接套用最新 MuJoCo 的求解器功能。

下一步是 F2：解除 F1 的局部姿态固定，按名称与局部参考坐标适配两段视频的抓取。接入前先检查这种残余抖动是否影响接触判定与场景碰撞裕量。当前没有整桌抓取成功率，也没有验证带载搬运。

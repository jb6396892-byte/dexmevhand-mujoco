# 从 DexYCB 视频学习抓杯：实施设计

## 目标和当前边界

目标是让策略在 MuJoCo 中依据观测自主完成 `reach -> grasp -> lift -> transport`，然后再扩展到更多真实视频、杯子初态与视角。第一版使用状态输入和 `relocate-mug-0.8`；视频直接到 30 维动作的端到端模型留到状态策略稳定之后。

截至 2026-09-26，已完成一条真实 DexYCB 右手 `025_mug` 序列的 RGB-D、MANO、杯子 6D 位姿转换和重定向。此前的 20 次 DAPG 短训策略能运行，但独立回放没有抓起杯子。[旧策略物理结果](run_logs/2026-09-25-policy-physics.md)。随后修复了几何与连续动作，从该**同一条视频**构建出六条仅改变初态毫米级位置的物理示范。示范在 11 个近邻初态中通过自由杯子动力学检查，尚未用这些新示范训练出策略。[物理示范验收](run_logs/2026-09-26-physical-grasp-training-ready.md)。

六条扰动示范不是六条独立真实视频；它们只能用于第一轮窄初态训练和接口验证。

## 学习问题的拆分

DexYCB 给出的是人手与物体随时间变化的**状态**，而 `YCBRelocate.step()` 要求的是 Adroit 执行器的 30 维归一化**动作**。人手和 Adroit 的尺寸、关节与碰撞几何不同；视频也没有执行器力和接触力标签。因此分为两级：

```text
真实 RGB-D + 标定 + MANO/物体标签
    -> 相机/世界坐标、尺度和时间对齐
    -> 人手相对杯子的姿态与技能目标
    -> 带接触与关节约束的 Adroit 重定向
    -> 100 Hz 可执行轨迹与控制器
    -> 杯子自由运动的 env.step(action) 验收
    -> (observation, action, reward, sim_state) 示范
    -> BC 初始化 -> DAPG 物理微调 -> 未见过初态/序列评估
```

前半段学习“手应该怎样接近和抓住杯子”，后半段学习“Adroit 应发出什么动作才能稳定接触”。杯子位姿只能用于轨迹生成的参考和任务目标；动态验收中不得逐帧写入杯子 qpos。动作传给 `YCBRelocate.step()` 前只归一化一次。

## 阶段 0：完成首轮窄初态训练

现有可检查产物：`scripts/21_diagnose_geometry.py`、`22_repair_geometry.py`、`24_search_physical_grasp.py`、`25_export_verified_grasps.py`、`26_train_verified_curriculum.py`、`28_view_verified_grasp_gpu.sh`；本地生成数据由 `.gitignore` 排除。

1. 运行 `bash scripts/27_train_verified_smoke.sh`：核对示范 SHA-256、39/30 维数据、1000 步课程复位、采样器重放和 CUDA。
2. 运行 `bash scripts/27_train_verified_smoke.sh --train`：只做 20 次 DAPG 短训练；检查 BC、采样、更新、有限参数和独立 checkpoint。
3. 对新策略做独立物理评估，至少覆盖训练课程中的不同复位种子；逐条记录杯底高度、真实接触力、接触持续时间、目标距离、最大穿透和动作饱和率。保留旧短训策略作为失败基线。
4. 只有学到的策略在课程分布上稳定抬杯，才继续扩大初态范围或提高训练迭代数。示范控制器成功不算策略成功。

阶段产出：新的训练日志、策略 checkpoint、逐种子物理评估报告。20 次迭代无 NaN 和维度错误只是**训练链路通过**；策略仍须单独通过动力学抓取检查。

## 阶段 1：增加独立真实轨迹

优先扫描共享盘已有 DexYCB Subject 01 的其他右手 mug 序列；数量不够时再按许可补充其他受试者，不重复下载现有文件。每条记录 `subject`、原始 sequence、camera、FPS、有效帧、是否包含完整接近/闭合/抬起、手侧、物体 ID 和数据版本。

具体操作：

1. 用 `scripts/09_scan_dexycb.py` 列候选；优先选择不同初始杯子位置、朝向和抓持方式的完整序列。
2. 用 `scripts/10_convert_dexycb.py` 转换，每条单独输出目录；保留原始帧号映射和缺失帧标记。
3. 用 `scripts/11_visualize_source_pose.py` 重投影手关节和杯子；逐条审核尺度、坐标轴、时间同步和源视频中的真实抬杯。
4. 建立数据清单和排除原因；按**原始序列**划分训练/验证/测试，同一序列的不同相机和扰动副本不能跨集合。

首轮目标是至少获得 3 条相互独立、审核通过的 mug 序列，再报告它们的抓持差异。这个数量只是开始评估多序列流程的最低目标，不足以证明跨人或跨物体泛化。若只有 Subject 01，所有跨受试者结果都标为未验证。原始视频、相机数据和 MANO 文件留在共享盘或本地忽略目录。

## 阶段 2：学习可执行的抓持目标

对每条视频恢复 `MANO` 手姿态与 mug 6D 位姿，转成以杯子为中心的手腕/指尖相对轨迹。先做明确的关键事件分段：接近、首次指尖接触、闭合、杯底离桌、运输和保持；低置信度帧与遮挡片段单独标记，不把自动估计当成确定真值。

重定向时保持共同的坐标与 `object_scale=0.8`，在 MuJoCo 碰撞模型中约束手杯穿透、关节范围和帧间速度/加速度。源序列是 30 FPS，仿真控制为 100 Hz；100 Hz 轨迹和物理子步也要检查，不能只验源帧。记录原视频投影误差、指尖目标误差、最大穿透和哪些帧的目标无法到达。

首轮模型可以用监督学习预测 `grasp` 姿态或相对杯子的关键路点；训练输入为手杯相对状态和任务目标，标签为通过几何审核的关键姿态。不要用只有姿态而没有物理验收的轨迹直接当 DAPG 示范。

## 阶段 3：从目标生成并筛选物理动作

对每条重定向轨迹构造平滑的接近、闭合、抬升和保持参考；利用 Adroit 执行器增益/偏置、关节反馈和 MuJoCo 自由杯子动力学求动作。必要时搜索闭合幅度与手相对杯子的毫米级偏移，但这些参数必须有来源记录，不能逐帧强制搬运杯子。

逐条保存原始 `source_sequence`、姿态算法版本、retarget 配置、动作生成参数、仿真模型、接触/穿透曲线和随机种子。示范准入至少检查：

- 从同一初态重新执行**保存的动作**，状态与原 rollout 一致。
- 持续有力接触且杯底离桌，保持阶段不滑落。
- 穿透、动作饱和和目标距离达到明确门槛；未通过的序列保留失败报告，不混入训练集。
- 使用多个近邻初态复测；这些扰动副本仍归属原始视频的同一数据划分。

当前第一条序列的门槛见 `src/fromrealhand/grasp_gate.py`；随着环境或任务变化应重新审查门槛，不直接把这一次通过视为通用成功标准。

## 阶段 4：模仿学习与强化学习

将物理通过的 rollout 转成 DexMV 所需字段：`observations/actions/rewards/sim_data/model_data`。先用 BC 学 `pi(action | observation, goal)`，评估未见过的**初态**；再用 DAPG 在 MuJoCo 中采样和微调，逐步扩大杯子位置、朝向、手的初始距离及扰动范围。当前 `YCBRelocate` 观测只有 39 维，新增技能/目标条件前需明确修改观测与策略输入的版本，不把新旧 checkpoint 混用。

评估至少分三层记录：

| 层次 | 通过条件 | 当前状态 |
| --- | --- | --- |
| 数据与几何 | 标签、投影、坐标、尺寸和轨迹连续性可信 | 首条序列已检查；多序列未完成 |
| 专家物理示范 | 保存动作可独立重放，杯子自由运动并持续抬起 | 首条序列的窄初态课程已通过 |
| 学到的策略 | 独立复位和未见过序列上由策略自主 `env.step(action)` 抓起杯子 | 新示范尚未训练；旧短训策略未通过 |

结果报告成功率、样本数和置信区间，同时保留失败类型：没接触、碰撞过深、滑落、目标偏差和动作饱和。只有前一层通过才扩大训练和任务难度；不能用 reward 上升或能打开仿真窗口代替抓取成功。

## 后续：技能与语言

多序列状态策略稳定后，再把 `reach/grasp/lift/transport` 拆为可复用技能，训练成功判别和失败恢复。高层先用确定性结构化计划验证调用顺序，再考虑语言模型生成计划；高层输出技能与目标，低层策略负责 MuJoCo 动作。倒水技能和目标容器属于之后的独立阶段，见[架构文档](ARCHITECTURE.md)。

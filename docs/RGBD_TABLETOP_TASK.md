# RGB-D 桌面视觉抓杯任务书

日期：2026-10-03。原任务书保留如下；前三步基础版的实际选型、结果与边界见 [执行进展](RGBD_TABLETOP_PROGRESS.md)。目前不推进第 4 步控制适配。

## 已确认范围

用户确认本轮先完成仿真桌面与虚拟 RGB-D，继续使用现有 Adroit，之后再接真实设备。本轮的“真实场景”指有生活物体、纹理、光照和遮挡的桌面仿真，不代表已经部署到实物。

第一版目标：桌面放置训练使用的 `025_mug` 和 3 至 5 件干扰物，输入“抓起桌上的杯子”，系统从 RGB-D 自动识别并估计杯子位姿，经高层计划与低层控制将杯子抓起并保持，Qt 显示感知、控制和物理结果。先只有一个目标杯子，正放、低遮挡、抓取路径无阻挡；暂不做任意杂乱堆叠、复杂绕障、倒水或更换手型。

## 现有基础与缺口

- 可复用：训练杯子网格与碰撞模型、Adroit、旧稳定策略、技能执行框架、LoRA 高层、Qt 与已修复的 GPU 渲染启动器。
- 当前 Qt 的低层是两标准场景的已验证专家参考动作，不是根据视觉坐标自动调整的抓取网络，见 `QT_DESKTOP.md`。
- 当前残差采样代码使用环境观测、`qpos/qvel`、时间/参考动作等信息，见 `src/fromrealhand/residual_sampling.py`。不能仅替换一个 xyz 就宣称完成视觉部署，需要逐项审计观测和参考依赖。
- 缺少桌面场景、虚拟深度相机、自动检测/分割、6D 位姿估计、感知驱动的控制适配与新场景验收。旧策略的毫米级扰动测试不能证明新桌面任务可用。

## 开源选型

| 模块 | 已查到的来源 | 本项目建议 |
| --- | --- | --- |
| 轻量桌面 | [robosuite TableArena](https://robosuite.ai/docs/modeling/arena.html)、[桌面 XML](https://github.com/ARISE-Initiative/robosuite/blob/master/robosuite/models/assets/arenas/table_arena.xml) | 第一优先：复用桌面结构与必要资产，适配现有 MuJoCo，不直接更换机器人 |
| 生活环境 | [RoboCasa 场景](https://robocasa.ai/docs/build/html/assets/scenes.html)、[源码](https://github.com/robocasa/robocasa) | 可选取少量台面/背景资产；完整厨房留到后续，不先下载整库 |
| RGB-D 接口参考 | [robosuite Sensors](https://robosuite.ai/docs/modules/sensors.html) | 参考相机观测接口，在当前引擎实现并验证深度与坐标约定 |
| 杯子检测与分割 | [Grounded SAM 2](https://github.com/IDEA-Research/Grounded-SAM-2) | 候选使用本地 Grounding DINO + SAM 2 分支，自动生成杯子 mask；先测显存和延迟，不使用云端 API 分支 |
| 位姿估计 | [FoundationPose 源码](https://github.com/NVlabs/FoundationPose)、[CVPR 2024 论文](https://openaccess.thecvf.com/content/CVPR2024/papers/Wen_FoundationPose_Unified_6D_Pose_Estimation_and_Tracking_of_Novel_Objects_CVPR_2024_paper.pdf) | 已知杯子 mesh + RGB-D + 内参 + 自动 mask，估计位置和朝向；模型不能代替检测/分割 |

选型为工程建议，不是已验证兼容。现代 robosuite/RoboCasa 与现有旧 MuJoCo/Python 环境不能直接视为兼容；先检查资产 XML、碰撞与许可证，冻结采用版本。视觉模型放独立环境，不升级 `dexmv`。FoundationPose 代码采用 NVIDIA 专用许可证，使用与分发前记录对应条款，不按 MIT 处理。

## 系统链路

```text
中文指令 -> LoRA 高层 -> 合法技能计划
虚拟 RGB-D -> 杯子检测/分割 -> 6D 位姿估计与跟踪
相机坐标位姿 -> 标定变换 -> 世界/手基座坐标位姿
计划 + 估计位姿 + 手部本体状态 -> 可达性检查与低层控制
env.step(action) -> 物理抓取 -> RGB-D/状态反馈 -> Qt
```

杯子中心坐标不足以确定抓法，还需杯柄朝向、尺度和抓取参考。使用训练时相同尺度与原点约定，先核对现有 `object_scale=0.8` 的实际作用，避免 mesh 和位姿估计重复缩放。仿真自由相机只用于观察，不替代固定的感知相机。

## 执行阶段

| 顺序 | 工作 | 产物与验收 |
| --- | --- | --- |
| 1 | 冻结旧版本，核对控制输入；引入桌面、训练杯和少量其他物体，设置固定 RGB-D 相机 | 独立场景 XML、资产/许可证清单、可重复种子；无初始穿模，旧场景回归通过 |
| 2 | 输出同步 RGB、米制深度、内外参、时间戳；统一 OpenGL/OpenCV 坐标和图像翻转 | 相机接口、深度图和点云；已知几何投影/反投影测试通过。此步可用真值作诊断，不计视觉成功 |
| 3 | 接入自动检测/分割及 FoundationPose；输出杯子 6D 位姿、质量指标和跟踪状态 | 感知报告与叠加图；无目标/多义目标/低质量估计时拒绝执行；无需人工每次点选或提供真值 mask |
| 4 | 先用真值位姿诊断控制上限，再改为视觉位姿；检查机器人可达性和动作连续性 | 原专家基线与旧稳定学习策略分开测试；逐项替换物体真值观测，必要时加入物体相对参考、局部闭环修正或小规模训练 |
| 5 | 增加新桌面场景的高层契约和可行性校验，接入 Qt；不改旧冻结准入凭据 | 指令到抓取全链路；显示 RGB/深度/仿真、目标叠加与参数，支持重定位、执行、停止、日志和截图 |
| 6 | 冻结候选，使用新留出布局对照测试，加入深度噪声与轻度遮挡 | 成功率、误差/耗时分布、失败分类；2 至 3 张截图、命令、版本和答辩资料 |

阶段 4 是主要技术风险。优先复用旧学习策略，但不假定它已能泛化；专家参考只能作诊断或对照。若最后仍只有专家控制通过，明确交付为“视觉驱动专家抓取”，不能称为训练模型部署完成。新增底层训练前说明修改范围和预算，不自动启动长训练。

## Qt 新增信息

- 固定相机 RGB、米制深度、杯子检测框/mask、位姿坐标轴；与原有自由视角仿真画面分开展示。
- 杯子相机系/世界系 xyz（mm）、朝向（明确角度或四元数约定）、目标 ID、检测分数与位姿质量指标。不得把未经标定的匹配分数当作成功概率。
- 相机分辨率/帧率、帧时间、感知耗时、估计结果时龄、跟踪有效性和丢失次数。
- 可达性、所用低层后端、阶段、抓取成败原因；保留杯底高度、接触力、穿透、动作幅值等原参数。
- 真值位姿与误差只放“评测”区域，明确标注仿真真值，不显示成 RGB-D 测量结果。

## 建议首版验收

以下是待开发预检后冻结的目标，不是当前已达到的结果；最终测试前固定布局、阈值和随机种子。

1. 场景含目标杯与 3 至 5 件不同干扰物。先在可达范围内做杯子位置约 ±2 cm、偏航约 ±15 度的变化，再依据开发结果明确扩大范围；桌面外不可达区域不得算作已支持。
2. 感知初始目标：定位误差中位数不超过 5 mm、95 分位不超过 10 mm；朝向误差中位数不超过 10 度，并单列杯柄方向失败。控制是否容忍该误差必须用噪声注入测试验证，定位过线不等于能抓取。
3. 固定至少 20 个未参与调参的布局，视觉模式完整任务成功目标不低于 16/20。抓起定义为杯底离桌至少 5 cm，并持续保持 2 秒；不能用相机系 z 或静止截图判定。
4. 同布局分别测试真值输入、视觉输入和原固定参考动作；报告全部失败和定位拒绝，拒绝不从端到端成功率分母中删除。
5. 保留原 1 mm 数值穿透上限与关节限位检查；不得通过关接触、改杯子位姿或增大穿透容忍掩盖失败。干扰物碰撞、误抓、掉杯、超时分别记录。
6. 正式视觉控制不能读取杯子真值位置/姿态/速度或真值 mask；物体速度等输入应从感知估计。机器人本体状态可用仿真关节传感，接触力须标明仿真触觉。独立评测可读真值，但不能反馈给控制或技能成功判断冒充视觉能力。
7. 丢失、低质量、结果过期、不可达或指令越界时进入有界保持/安全停止，不悄悄切换为真值控制。测试停止和故障恢复。

## 交付和保存

拟新增 `src/fromrealhand/perception/`、`src/fromrealhand/tabletop/`、桌面/相机配置、独立运行及验收脚本；扩展现有 Qt，不另建不相连的演示器。每阶段保存小型报告和少量关键截图，记录所用源码、许可证、参数和失败原因。

代码与小型答辩资料留在当前项目；大场景资产和新视觉权重单独放 `/media/smgbro/shared/visual_grasp/`，不与阶段 6 的 `lora/language/` 混用，不移动阶段 3 产物。具体安装和下载记录以执行进展为准。

接实物作为后续独立阶段，届时需要相机/机械臂/手型号、相机与机器人标定、控制与急停接口、延迟与噪声验证；不能仅把虚拟 RGB-D 替换成相机流就直接运行真实设备。
